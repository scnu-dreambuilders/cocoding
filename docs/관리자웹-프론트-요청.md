# 관리자 웹 — 프론트엔드 작업 요청서

회원과 운영 기준값을 관리하는 **관리자 웹**의 서버 기능이 준비됐습니다. 화면이 없어서 지금은 쓸 수 없습니다. 이 문서는 어떤 화면이 필요한지와 서버가 무엇을 주고받는지 정리한 것입니다.

서버 구현은 `backend` 브랜치(PR #14)에 있습니다. 이 문서만으로 작업할 수 있게 응답 모양을 전부 적어 뒀습니다.

---

## 0. 먼저 알아야 할 것

### 관리자는 역할(role)이 아니라 플래그입니다

`users.role`은 그대로 `student`·`teacher`·`guardian`입니다. 관리자는 **`is_admin`** 이라는 별도 플래그입니다. 선생님 계정에 운영자 권한이 함께 있을 수 있습니다.

로그인 응답과 `/api/social/profile.php`의 사용자 객체에 `is_admin`이 들어오지 않습니다. 관리자 여부는 **관리자 API를 한 번 불러보고 403이 오는지로** 판단하거나, 관리자 웹을 아예 별도 앱으로 만들고 "권한 없음" 화면을 보여주는 쪽이 간단합니다. 사용자 객체에 `is_admin`을 넣어 달라고 하시면 추가하겠습니다.

### 별도 앱으로 만드는 걸 권합니다

학생용 화면과 섞으면 번들이 커지고, 학생 화면에 관리자 코드가 들어갑니다. `admin/` 같은 별도 Vite 앱으로 두고 다른 포트에서 띄우는 쪽을 권합니다.

**별도 주소로 띄우면 `backend/.env`의 `ALLOWED_ORIGINS`에 그 주소를 넣어야 합니다.** 지금은 `5173,5174,5175`만 들어 있습니다. 쓰실 포트를 알려주시면 제가 추가해 두겠습니다.

### 공통 응답 모양

기존 API와 같습니다.

```
성공  { "success": true,  "data": { ... } }
실패  { "success": false, "error": "사람이 읽을 수 있는 한국어" }
```

`error`는 그대로 화면에 띄워도 되는 문장입니다. 따로 문구를 만들지 않으셔도 됩니다.

| 상태 | 뜻 | 화면 |
|---|---|---|
| 401 | 로그인 안 됨 / 토큰 만료 | 로그인 화면으로 |
| 403 | 운영자가 아님 | "권한 없음" 화면 |
| 400 | 보낸 값이 잘못됨 | `error`를 그 자리에 보여주기 |
| 404 | 그런 회원·글이 없음 | 목록으로 돌려보내기 |

요청에는 `Authorization: Bearer <토큰>`이 필요합니다. 기존 `api/client.js`와 같습니다.

## 1. 대시보드

```
GET /api/admin/stats.php
```

```jsonc
{
  "users": {
    "total": 52, "byRole": { "student": 49, "teacher": 3 },
    "admins": 1, "suspended": 0, "consentPending": 4,
    "newToday": 2, "activeWeek": 11
  },
  "signups7d": [ { "day": "2026-11-14", "count": 3 }, ... ],   // 7칸, 날짜 오름차순
  "learning":   { "chaptersDone": 83, "projects": 120, "publicProjects": 44 },
  "board":      { "posts": 31, "questions": 12, "solved": 7, "comments": 58 },
  "moderation": { "hiddenPosts": 1, "hiddenProjects": 0, "openPostReports": 2 },
  "coins":      { "granted": 4210, "spent": 1800, "held": 2410 }
}
```

**화면 제안** — 숫자 카드 몇 개(전체 회원 / 오늘 가입 / 최근 7일 활동 / 보호자 동의 대기 / 정지 계정)와 `signups7d` 막대그래프. `moderation`에 0이 아닌 값이 있으면 "확인할 신고 N건" 배지를 띄워 신고 화면으로 보내는 흐름이면 좋을 것 같습니다.

- `activeWeek`는 **접속자 수가 아닙니다.** 최근 7일에 코인이 오간 사람 수입니다(출석·챕터·작품 저장·게임 중 하나라도 한 사람). 접속 시각을 따로 저장하지 않아서 이렇게 셉니다. 화면에는 "활동한 학생" 정도로 적어주시는 게 뜻에 맞을 것 같습니다
- `openPostReports`는 신고가 들어왔지만 아직 숨겨지지 않은 글 수입니다
- `coins.held`는 지금 학생들이 들고 있는 코인 합계입니다. `granted - spent`와 꼭 같지는 않습니다(관리자가 계정을 지우면 그 사람 코인이 사라지므로)

## 2. 회원 목록

```
GET /api/admin/users.php?page=1&q=&role=&state=
```

| 조건 | 값 | 설명 |
|---|---|---|
| `page` | 1부터 | 한 쪽에 20명 |
| `q` | 글자 | 닉네임 또는 이메일 부분 일치 |
| `role` | `student`·`teacher`·`guardian` | 비우면 전체 |
| `state` | `suspended`·`admin`·`pending` | 정지된 / 운영자 / 보호자 동의 대기 |

```jsonc
{
  "users": [
    {
      "id": 52, "username": "코코딩관리자", "email": "admin@cocoding.co.kr",
      "role": "teacher", "level": 1, "xp": 0, "coins": 0,
      "is_admin": true, "suspended": false, "suspended_reason": null,
      "consent_status": "not_required", "affiliation": "코코딩 운영팀",
      "created_at": "2026-11-18 10:53:23"
    }
  ],
  "hasMore": false,
  "total": 52        // 조건에 맞는 전체 인원 (쪽 수 계산용)
}
```

- `is_admin`·`suspended`는 **불린**입니다 (0/1이 아닙니다)
- `q`에 `%`나 `_`를 넣어도 글자 그대로 찾습니다. 서버에서 막아 뒀습니다
- 정렬은 가입 역순(`id DESC`)으로 고정입니다. 다른 정렬이 필요하면 알려주세요

**화면 제안** — 검색창 + 역할 탭 + 상태 필터, 표에는 닉네임·이메일·역할·레벨·코인·가입일. 운영자는 뱃지, 정지된 계정은 행을 흐리게. 행을 누르면 상세로.

## 4. 회원 상태 바꾸기

```
PATCH /api/admin/users.php?id=52
```

**보낸 항목만 바뀝니다.** 한 번에 여러 개 보내도 됩니다.

| 보내는 값 | 형 | 설명 |
|---|---|---|
| `role` | `'student'`·`'teacher'`·`'guardian'` | 계정 유형 |
| `is_admin` | `true`/`false` | 운영자 권한 |
| `suspended` | `true`/`false` | 계정 정지 / 해제 |
| `suspended_reason` | 글자 (100자) | 정지 사유 — **학생 화면에 그대로 보입니다** |
| `consent` | `'granted'` | 보호자 동의를 운영자가 대신 승인 |
| `force_logout` | `true` | 이 사람의 모든 토큰 무효화 |
| `email` | 글자 | 이메일 바꾸기 (다른 사람이 쓰고 있으면 409) |
| `coins_delta` | 정수 | 코인 **더하기·빼기** (절대값이 아닙니다. `10` / `-10`) |
| `xp_delta` | 정수 | 경험치 더하기·빼기 |
| `reset_password` | `true` | 임시 비밀번호 발급 |

응답은 바뀐 뒤의 `user`·`summary`와 `message`입니다.

```jsonc
{ "user": {...}, "summary": {...},
  "message": "회원 정보를 바꿨어요. 이 회원은 다시 로그인해야 해요." }
```

### 함께 봐주시면 좋을 것들

**정지할 때 사유를 같이 보내주실 수 있을까요?** 사유는 정지된 학생이 앱을 켰을 때 보이는 문장에 들어갑니다. 비워 두면 "이 계정은 지금 쓸 수 없어요"만 보여서, 학생이 왜 막혔는지 알 수 없게 됩니다.

```jsonc
{ "suspended": true, "suspended_reason": "다른 친구에게 나쁜 말을 했어요" }
```

**정지를 풀면 사유도 함께 지워집니다.** `{ "suspended": false }`만 보내시면 됩니다.

**아래 네 가지는 서버가 400으로 거절합니다.** 눌러본 뒤 거절당하는 것보다는 버튼을 아예 비활성화해 두시는 쪽이 운영자에게 친절할 것 같습니다.

- 자기 운영자 권한 빼기
- 자기 계정 정지
- 자기 계정 삭제
- **마지막 운영자**의 권한 빼기 (운영자가 1명일 때)

운영자인 회원을 삭제하려 하면 "운영자 권한을 먼저 빼고 지워주세요"로 거절합니다.

**`message`에 "다시 로그인"이 들어오면** 그 회원이 로그아웃됐다는 뜻입니다. 역할·운영자 권한이 바뀌거나 정지됐을 때 서버가 토큰을 끊습니다. 목록으로 돌아갈 때 새로 불러주시면 화면과 서버가 어긋나지 않습니다.

### 코인·경험치는 "더하기·빼기"입니다

`coins_delta: -30`을 보내면 30을 뺍니다. **지금 값을 100으로 맞추는 게 아닙니다.** 화면에서 "지금 120 → 100으로"를 하시려면 `-20`을 계산해서 보내주셔야 합니다. 둘 다 0 밑으로는 내려가지 않습니다.

코인은 `coin_log`에 `reason='admin'`으로 남아서, 나중에 왜 늘었는지 되짚을 수 있습니다.

### 임시 비밀번호는 한 번만 보입니다

```jsonc
// PATCH { "reset_password": true } 의 응답
{ "user": {...}, "summary": {...},
  "tempPassword": "Kq7mBnP2xR!",
  "message": "임시 비밀번호를 만들었어요. 이 화면을 닫으면 다시 볼 수 없어요." }
```

서버는 해시만 저장하므로 **다시 볼 수 없습니다.** 운영자가 받아 적거나 복사할 수 있게 화면에 크게 보여주고 복사 버튼을 붙여주시면 좋겠습니다. 받아 적기 쉽게 섞이는 글자(`0 O 1 l I`)는 빼고 만듭니다.

발급하면 그 계정은 로그아웃됩니다.

```
DELETE /api/admin/users.php?id=52
```

탈퇴 처리입니다. **되돌릴 수 없습니다.** 작품·글·댓글이 함께 사라집니다. 누르기 전에 확인 창을 띄워주시면 좋겠습니다. 닉네임을 직접 입력하게 하는 식이면 더 안심이 될 것 같습니다.

## 5. 운영 기준값

```
GET /api/admin/settings.php
```

```jsonc
{
  "settings": [
    {
      "name": "coin.chapter",
      "group": "코인",
      "label": "챕터 첫 완료 코인",
      "help": "챕터를 처음 끝냈을 때 한 번만 주는 코인이에요.",
      "min": 0, "max": 1000,
      "value": 50,       // 지금 값
      "default": 50,     // 코드에 적힌 기본값
      "changed": false   // 기본값에서 바뀌었는지
    }
  ]
}
```

**항목을 화면에 하드코딩하지 않으시는 쪽을 권해 드립니다.** `settings` 배열을 돌면서 `group`으로 묶고, `label`·`help`·`min`·`max`로 입력칸을 그려주시면 됩니다. 그렇게 해 두면 나중에 기준값을 추가할 때 프론트를 같이 고치지 않아도 되어서요.

지금 들어 있는 항목은 9개입니다.

| group | 항목 |
|---|---|
| 코인 | 출석 / 연속 출석 보너스 / 챕터 첫 완료 / 자유 창작 첫 저장 / 타자게임 정답 / 복습 퀴즈 정답 |
| 코코 대화 | 하루 질문 횟수 |
| 신고 | 자동 숨김 신고 수 |
| 게시판 | 글쓰기 간격(초) |

`changed`가 `true`인 항목에 "기본값으로 되돌리기" 버튼이 있으면 쓰기 편할 것 같습니다 (`default`를 함께 보여주셔도 좋겠습니다).

```
PUT /api/admin/settings.php
{ "values": { "coin.chapter": 70, "coco.daily_limit": 20 } }
{ "reset":  ["coin.chapter"] }
```

둘을 한 번에 보내도 됩니다. 응답은 이렇습니다.

```jsonc
{
  "settings": [ /* 저장 후의 전체 목록 — 이걸로 화면을 다시 그리면 됩니다 */ ],
  "saved": ["coin.project"],
  "errors": { "coin.chapter": "챕터 첫 완료 코인은 0부터 1000까지만 넣을 수 있어요." },
  "message": "1개 기준값을 저장했어요. 1개는 저장하지 못했어요."
}
```

**전부 되거나 전부 안 되는 식이 아닙니다.** 범위를 벗어난 항목만 거절하고 나머지는 저장합니다. `errors`의 키가 항목 이름이라, **그 입력칸 아래에 메시지를 붙여주시면** 저장 버튼 하나로 여러 칸을 함께 보내도 어디가 틀렸는지 바로 보여줄 수 있습니다.

> 기준값은 바꾸면 **바로 반영됩니다.** 캐시가 없습니다. 코인 금액을 잘못 넣으면 그 순간부터 그 금액으로 지급되니, 큰 값을 넣을 때 한 번 더 확인하는 창이 있으면 좋겠습니다.

## 6. 신고된 글·작품

```
GET /api/admin/moderation.php?target=post&page=1      // target: post | project
```

```jsonc
{
  "items": [
    { "id": 12, "title": "시험 글", "kind": "discussion", "hidden": false,
      "created_at": "...", "user_id": 7, "username": "코딩하는곰",
      "reports": 2, "target": "post" }
  ],
  "hasMore": false,
  "target": "post",
  "hideCount": 3      // 이 인원이 신고하면 자동으로 숨겨집니다
}
```

신고가 하나라도 있거나 이미 숨겨진 것만 나옵니다. 신고 많은 순 → 최신 순입니다. `reports`가 `hideCount`에 가까운 것을 눈에 띄게 해 주시면 좋겠습니다.

작품(`target=project`)은 `kind` 대신 `is_public`이 옵니다.

```
GET /api/admin/moderation.php?target=post&id=12
→ { "target": "post", "id": 12,
    "reasons": [ { "reason": "광고·도배", "created_at": "..." } ] }
```

**판단하려면 신고 이유를 봐야 해서**, 상세를 열 때 이걸 같이 불러주시면 좋겠습니다.

```
PATCH /api/admin/moderation.php?target=post&id=12
{ "hidden": true }    // 또는 false 로 복구
```

- 숨기면 작성자 말고는 볼 수 없습니다. **지우는 기능은 없습니다** — 되돌릴 수 없어서 일부러 두지 않았습니다
- 복구해도 **신고 기록은 남습니다.** 왜 숨겨졌는지 남아 있어야 다음 판단을 할 수 있어서입니다. 기록이 남아 있어도 자동으로 다시 숨겨지지는 않습니다
- **운영자는 숨겨진 글도 읽을 수 있습니다.** 숨긴 뒤에 내용을 봐야 복구할지 판단할 수 있어서 열어뒀습니다. 위 `?id=N` 응답에 글 본문과 댓글이 함께 오고(`post`·`comments`), 기존 `GET /api/board/index.php?id=N`으로도 열 수 있습니다
- 작품은 `blocks_data`(수백 KB)를 빼고 제목·무대 캡처(`thumbnail_url`)만 옵니다

## 6-1. 공지사항

```
GET    /api/admin/notices.php?page=1      목록 (초안까지 보입니다)
GET    /api/admin/notices.php?id=N        하나
POST   /api/admin/notices.php             { title, body, pinned?, published?, audience? }
PATCH  /api/admin/notices.php?id=N        보낸 항목만 바뀝니다
DELETE /api/admin/notices.php?id=N        지우기 (되돌릴 수 없습니다)
```

| 항목 | 값 | 설명 |
|---|---|---|
| `title` | 1~80자 | |
| `body` | 1~2000자 | |
| `pinned` | 불린 | 맨 위 고정. 여러 개 고정해도 됩니다 |
| `published` | 불린 (기본 `true`) | **끄면 초안** — 운영자만 보이고 학생 화면에 안 나옵니다 |
| `audience` | `all`·`student`·`teacher`·`guardian` (기본 `all`) | 받는 사람 |

**초안 기능도 화면에 함께 넣어주실 수 있을까요?** 급한 공지를 쓰다 말고 저장해도 학생에게 반쯤 쓴 글이 보이지 않게 하려고 둔 것입니다. "올리기" / "초안으로 저장" 두 버튼으로 나누면 좋을 것 같습니다.

학생·선생님·보호자가 읽는 쪽은 **별도 주소**입니다. 운영자 전용이 아니라 로그인만 하면 됩니다.

```
GET /api/notices.php
→ { "notices": [ { id, title, body, pinned, audience, created_at, updated_at } ] }
```

내 계정 유형에게 보이는 것만, 고정된 것이 위로, 최근 20개가 옵니다. 초안은 절대 안 나옵니다. **학생 화면(홈이나 마이페이지)에 이걸 보여주는 작업도 함께 부탁드려도 될까요?** 공지를 써도 학생이 볼 곳이 없으면 의미가 없어서요.

## 6-2. 챕터 내용

```
GET /api/admin/chapters.php            전체 + 학생 몇 명이 하고 있는지
GET /api/admin/chapters.php?id=N       하나
PUT /api/admin/chapters.php?id=N       { title, concept, mission, new_blocks, required_blocks, reward_item }
```

```jsonc
{
  "chapters": [ { "id": 1, "order_num": 1, "title": "...", "concept": "...", "mission": "...",
                  "new_blocks": ["when_key","move_x"], "required_blocks": ["when_key"],
                  "reward_item": "빨간 모자" } ],
  "usage": { "1": { "completed": 12, "inProgress": 3, "total": 15 } },
  "knownBlocks": ["broadcast", "change_size", "..."]
}
```

- `new_blocks`·`required_blocks`는 **배열**로 오고 갑니다 (DB에는 JSON 글자로 들어 있지만 서버가 바꿔줍니다)
- `knownBlocks`(42개)로 **드롭다운을 만들어주시면** 운영자가 잘못된 블록을 넣는 일이 없을 것 같습니다. 모르는 블록은 서버가 400으로 거절합니다 — 그 챕터 채점이 영원히 통과하지 못하게 되기 때문입니다
- `required_blocks`를 0개로 만들 수 없습니다 (무엇을 해도 통과하게 됩니다)
- **챕터를 새로 만들거나 지우는 길은 없습니다.** 챕터 수가 화면 코드(`CHAPTER_COUNT`)와 맞춰져 있어서입니다
- `usage.inProgress`가 0이 아닌 챕터의 미션이나 필요 블록을 고칠 때 **"지금 이 챕터를 하고 있는 학생 N명"** 경고가 있으면 좋겠습니다. 응답 `message`에도 같은 내용이 들어옵니다

## 6-3. 꾸미기 아이템과 상점

```
GET    /api/admin/items.php
PUT    /api/admin/items.php         { items: { 이름: {type, emoji, price?, source?} }, free_pool?: [...] }
DELETE /api/admin/items.php?name=왕관
```

```jsonc
{
  "items": [
    { "name": "왕관", "type": "hat", "emoji": "👑", "price": 80,
      "source": null, "ownedBy": 3, "chapterReward": [] }
  ],
  "freePool": ["왕관", "마법사 모자"],
  "types": ["hat", "glasses", "background", "accessory"]
}
```

- `price`가 있으면 상점에 나옵니다. **`null`로 보내면 상점에서 빠집니다** (아이템 자체는 남습니다)
- `source: "chapter"`면 챕터 완료 보상으로만 얻습니다
- `ownedBy`가 0보다 크거나 `chapterReward`가 비어 있지 않으면 **지울 수 없습니다.** 삭제 버튼을 비활성화해 두시면 좋겠습니다. 지우면 그 학생의 꾸미기가 깨지고, 챕터를 깬 학생이 받을 것이 없어져서 서버에서도 막아 뒀습니다
- `PUT`은 **보낸 아이템만** 바꿉니다. 전체를 보내지 않아도 됩니다
- `free_pool`(자유창작 보상 후보)에는 `items`에 있는 이름만 넣을 수 있습니다
- 학생 상점 응답의 이름 칸은 `item_name`입니다 (관리자 쪽은 `name`)

## 6-4. 선생님 반과 과제

```
GET    /api/admin/classes.php?page=1&q=      반 목록 (q: 반 이름 또는 선생님 닉네임)
GET    /api/admin/classes.php?id=N           반 + 학생 명단 + 과제 목록
DELETE /api/admin/classes.php?id=N           반 지우기
DELETE /api/admin/classes.php?assignment=N   과제 하나 지우기
```

**보기와 정리만 됩니다.** 반을 만들고 과제를 내는 건 선생님 일이라 운영자가 만들거나 고치는 길은 두지 않았습니다 — 운영자가 남의 반에 과제를 내면 선생님이 왜 생겼는지 알 수 없습니다.

참가 코드(`join_code`)도 그대로 옵니다. 선생님이 코드를 잊었을 때 알려줘야 하니까요.

반을 지우면 학생 명단과 과제가 함께 사라지지만 **학생 계정과 작품은 그대로**입니다. 확인 창에 그 점을 적어주시면 운영자가 덜 불안할 것 같습니다.

## 6-5. 운영 기록 보기

```
GET /api/admin/logs.php?channel=admin&date=2026-11-20&q=&limit=200
```

```jsonc
{
  "channel": "admin", "date": "2026-11-20",
  "dates": ["2026-11-20", "2026-11-19"],
  "channels": ["admin", "audit", "error", "access"],
  "lines": [ { "ts": "...", "rid": "...", "ev": "admin.user.update", "uid": 52 } ],
  "count": 12, "fileSize": 48210, "truncated": false, "retentionDays": 30
}
```

| 채널 | 무엇이 쌓이는지 |
|---|---|
| `admin` | **관리자 웹에서 한 일** (회원 변경·기준값·숨김·공지 등) |
| `audit` | 로그인·가입·탈퇴·신고처럼 나중에 확인할 일 |
| `error` | 오류와 예외 |
| `access` | 모든 요청 (양이 가장 많습니다) |

- `lines`는 **최근 것이 위**입니다. 줄마다 필드가 조금씩 다르니(`ev`에 따라 다름) 표로 딱 맞춰 그리기보다 `ts`·`ev`·`uid`를 열로 두고 나머지는 펼쳐보기로 두시는 쪽이 편하실 것 같습니다
- 줄이 깨져 있으면 `{ "raw": "..." }`로 옵니다. 그대로 보여주면 됩니다
- `truncated`가 `true`일 때 "최근 1MB만 보고 있어요" 같은 안내가 있으면 좋겠습니다
- 개인정보는 애초에 안 들어갑니다. 사용자는 번호(`uid`), 접속 지점은 되돌릴 수 없는 해시입니다

## 7. 화면 구성 제안

다섯 화면이면 됩니다. 순서대로 하시면 앞 화면이 뒤 화면의 바탕이 됩니다.

| 순서 | 화면 | 쓰는 API | 중요도 |
|---|---|---|---|
| 1 | 로그인 + 권한 없음 | 기존 `auth/login.php` + 관리자 API 403 확인 | 필수 |
| 2 | 대시보드 | `stats.php` | 필수 |
| 3 | 회원 목록 → 상세 → 상태 변경 | `users.php` | 높음 |
| 4 | 신고 관리 | `moderation.php` | 높음 |
| 5 | 공지사항 (+ 학생 화면에 공지 보여주기) | `admin/notices.php`, `notices.php` | 보통 |
| 6 | 운영 기준값 | `settings.php` | 보통 |
| 7 | 챕터 내용 | `chapters.php` | 낮음 |
| 8 | 아이템·상점 | `items.php` | 낮음 |
| 9 | 선생님 반·과제 | `classes.php` | 낮음 |
| 10 | 운영 기록 보기 | `logs.php` | 낮음 |

**1~4번까지면 실제로 운영할 수 있습니다.** 나머지는 나중에 붙여도 됩니다.

5번의 "학생 화면에 공지 보여주기"는 관리자 웹이 아니라 **학생 앱 쪽 작업**입니다. 공지를 써도 학생이 볼 곳이 없으면 의미가 없어서 함께 적었습니다.

디자인은 학생 화면처럼 둥글고 알록달록할 필요가 없습니다. 운영자가 보는 화면이라 **표와 숫자가 읽기 쉬운 쪽**이 좋습니다. 기존 `App.css`·`index.css`의 CSS 변수와 `rem` 기반 글씨 크기는 그대로 쓰시면 됩니다.

## 8. 첫 운영자 지정

관리자 웹은 운영자만 쓸 수 있는데, 처음에는 운영자가 한 명도 없습니다. **웹으로 자기를 운영자로 만드는 길은 일부러 두지 않았습니다** — 그런 길이 있으면 누구나 운영자가 될 수 있습니다.

개발하실 때는 서버에서 이렇게 지정하세요.

```
cd backend
php tools/make_admin.php 목록
php tools/make_admin.php 지정 내이메일@example.com
```

지정한 뒤 **다시 로그인**해야 합니다. 두 번째 운영자부터는 관리자 웹에서 지정할 수 있습니다.

## 9. 정리하면

부탁드리고 싶은 것을 모으면 이렇습니다. 화면 설계는 두 분이 더 잘 아시니, 아래는 서버 쪽에서 보이는 것만 적은 참고로 봐주시면 좋겠습니다.

1. 관리자 웹은 **별도 앱**으로 만드시는 쪽을 권해 드립니다 (쓰실 포트를 알려주시면 `ALLOWED_ORIGINS`에 추가해 두겠습니다)
2. 7번 표에서 **1~4번(로그인·대시보드·회원·신고)부터** 봐주시면 감사하겠습니다
3. 기준값·챕터 블록·아이템 종류는 서버가 주는 목록(`settings`·`knownBlocks`·`types`)으로 그려주시면, 나중에 항목이 늘어도 프론트를 같이 고치지 않아도 됩니다
4. 정지할 때 **사유를 같이 보내주시면** 학생이 이유를 알 수 있습니다
5. 되돌릴 수 없는 것(회원 삭제·공지 삭제·반 삭제)에는 확인 창이 있으면 좋겠습니다
6. **임시 비밀번호는 한 번만 보입니다.** 복사 버튼을 붙여주시면 좋겠습니다
7. 코인·경험치는 **더하기·빼기**라는 점만 유의해 주시면 됩니다. "지금 값으로 맞추기"가 아닙니다
8. 지울 수 없는 것은 버튼을 비활성화해 두시면 좋겠습니다 — 가진 학생이 있는 아이템, 챕터 보상으로 걸린 아이템, 운영자인 회원, 마지막 운영자의 권한, 자기 자신에 대한 정지·삭제·권한 빼기
9. 공지 화면에 **"올리기 / 초안으로 저장"** 두 버튼과, **학생 앱에서 공지를 보여주는 화면**도 함께 부탁드려도 될까요

아래는 아직 안 열어둔 것들입니다. 필요하시면 말씀만 해주시면 열어 두겠습니다.

- 사용자 객체에 `is_admin` 추가 (관리자 여부를 403 없이 알 수 있게)
- 회원 목록 정렬 바꾸기 (지금은 가입 역순 고정)
- 챕터를 새로 만들거나 지우기 (화면 코드도 같이 고쳐야 합니다)
- 운영자가 반을 만들거나 과제를 고치기
- `.env`(DB 비밀번호·`JWT_SECRET`·AI 키)는 **웹에서 고칠 수 있게 하지 않습니다**

응답 모양이 실제와 다르거나, 화면을 만들다 필요한 값이 빠져 있으면 편하게 말씀해주세요. 서버 쪽은 바로 고치겠습니다. 이 문서도 틀린 데가 있으면 알려주시면 고치겠습니다.
