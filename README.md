# Cocoding (코코딩)

> **"나만의 AI 단짝 친구와 함께 놀며 배우는 초등학생 맞춤형 블록 코딩 교육 플랫폼"**
> 코코딩(Cocoding)은 어렵고 지루하게 느껴질 수 있는 컴퓨터 프로그래밍을 초등학생의 눈높이에 맞춰 쉽고 재미있게 풀어낸 AI 기반 블록 코딩 교육 플랫폼 웹 서비스입니다. 아이들이 능동적으로 코딩 원리를 깨우치고 디지털 제작 능력을 키울 수 있도록 돕습니다.

---

## 프로젝트 개요 (Project Overview)

오늘날 코딩은 디지털 시대를 살아가는 아이들에게 필수적인 언어가 되었습니다. 하지만 복잡한 영문 텍스트 명령어를 입력하는 기존의 방식은 어린 학습자들에게 높은 진입 장벽이 됩니다.

**코코딩**은 이러한 문제를 해결하기 위해 친근한 **AI 캐릭터**를 전면에 내세웠습니다. 인공지능 캐릭터가 아이들에게 먼저 말을 걸고 상호작용하며, 마우스로 블록을 레고처럼 조립하는 '블록 코딩' 방식을 통해 자연스럽게 논리적 사고력을 기를 수 있도록 유도합니다. 단순히 정해진 정답을 맞히는 주입식 교육에서 벗어나, 아이들이 상상하는 무엇이든 자유롭게 창작할 수 있는 놀이터를 지향합니다.

## 핵심 기능 및 특징 (Key Features)

### 1. AI 캐릭터 중심의 동반 학습 (AI Companion)

* **친근한 멘토링:** AI 캐릭터가 학습자에게 맞춤형 질문을 던지거나 아이들의 관심사에 맞는 이야기를 나누며 코딩 학습에 대한 흥미를 지속적으로 유도합니다.
* **캐릭터 쇼룸 및 커스터마이징:** 미션 수행을 통해 얻은 보상으로 나만의 AI 캐릭터를 예쁘게 꾸밀 수 있는 아이템을 탐색하고 즉시 착용해 볼 수 있는 통합 상점 시스템이 포함되어 있어 성취감과 애착을 형성합니다.

### 2. 직관적인 블록 코딩 환경 (Block Coding Workspace)

* **단계별 미션 학습:** 기초 원리부터 차근차근 밟아 나가는 가이드 기반 학습 환경을 제공합니다.
* **자유 창작 에디터:** 정해진 규칙 없이 배경, 동물, 사물 등 다양한 그래픽 에셋과 코딩 블록을 활용하여 나만의 움직이는 동화, 게임, 애니메이션을 자유롭게 만들 수 있습니다.

### 3. 게이미피케이션 요소를 통한 높은 몰입도 (Gamification)

* **일일 미션 및 자동 출석:** 매일 접속할 때마다 자동으로 출석이 체크되어 보상이 지급되며, 오늘의 퀴즈나 타자 연습 같은 가벼운 미션을 수행하며 자연스러운 반복 학습을 유도합니다.
* **흥미진진한 미니게임 센터:** 알고리즘 기초 원리와 컴퓨터 과학 지식을 자연스럽게 배울 수 있는 재미있는 게임 중심의 학습 코너가 별도로 마련되어 있습니다.

### 4. 재미를 더하는 맞춤형 관심사 추천 (Random Topic Recommendation)

* **키워드 조합 추천:** AI 캐릭터가 재미있는 블록 코딩 주제를 맞춤형으로 추천하여 끊임없이 새로운 창작 아이디어를 제공합니다.

### 5. 선생님·보호자와 함께하는 안전한 학습 (Teacher & Guardian)

* **계정 유형:** 가입할 때 학생 / 선생님 / 보호자를 고릅니다. 학생은 나이 확인용 태어난 해만 받고, 실명·전화번호·학교는 받지 않습니다.
* **보호자 동의:** 만 14세 미만 학생은 대시보드에 보이는 동의 코드를 보호자가 입력해 동의해야 작품 공유·친구 작품 보기·리메이크를 쓸 수 있습니다. 챕터 학습과 작품 만들기는 동의 전에도 가능하며, 보호자는 연결을 끊어 언제든 동의를 철회할 수 있습니다.
* **선생님 반:** 선생님이 반을 만들면 참여 코드가 생기고, 코드로 들어온 학생들의 챕터별 진도·최고 점수를 한 표로 볼 수 있습니다.
* **리메이크 허용 선택:** 작품을 공유할 때 친구의 리메이크를 허용할지, 구경만 하게 할지 고릅니다.

## 서비스 대상 (Target Audience)

* **코딩을 처음 접하는 초등학생:** 글자를 많이 입력하지 않고도 마우스 클릭과 드래그만으로 프로그램을 뚝딱 완성해 보고 싶은 어린이
* **컴퓨터 과학에 흥미를 붙이고 싶은 학습자:** 게임, 퀴즈, 캐릭터 꾸미기 등을 통해 지루하지 않게 학습 습관을 형성하고 싶은 학생
* **자녀의 디지털 문해력을 키워주고 싶은 학부모:** 놀이 시간과 학습 시간을 유기적으로 연결하여 자녀에게 유익한 디지털 경험을 선물하고 싶은 보호자

## 기대 효과 (Expected Effects)

1. **논리적 사고력 및 문제 해결 능력 향상:** 블록을 연결해 하나의 완성된 프로그램이 움직이는 과정을 관찰하며 인과관계와 논리적 연산 구조를 직관적으로 이해하게 됩니다.
2. **창의적 표현력 확장:** 플랫폼 내에서 제공하는 다양한 키워드와 그래픽 요소를 융합하여 정답이 없는 자신만의 고유한 디지털 콘텐츠를 기획하고 제작할 수 있습니다.
3. **지속 가능한 자기주도 학습 유도:** AI 친구와의 상호작용, 일일 달성 보상, 캐릭터 성장 요소가 결합되어 어른들이 강제하지 않아도 아이 스스로 매일 접속하여 즐기는 건강한 학습 생태계를 구축합니다.
   
### 6. 매일 오게 만드는 장치 (Daily Loop)

* **출석 체크:** 하루 한 번 도장을 찍으면 코인을 받습니다. 연속으로 올수록 보너스가 붙고(최대 7일), 이번 달 달력에 출석한 날이 표시됩니다.
* **코인과 상점:** 출석 10, 챕터 완료 50, 작품 저장 5코인을 모아 코코 꾸미기 아이템 21종을 삽니다.
* **경험치·레벨·업적:** 학습 활동으로 경험치가 쌓여 레벨이 오르고, 첫 챕터 완료·만점·일주일 개근 같은 업적 9종을 모읍니다.
* **학습 기록:** 최근 2주 출석·챕터·작품을 막대그래프로 보고, 또래 평균과 견준 내 위치를 확인합니다.

### 7. 친구와 함께 (Community)

* **좋아요와 인기 작품:** 공개된 작품에 좋아요를 누르고, 친구 작품 탭을 인기순으로 볼 수 있습니다.
* **친구:** 서로 팔로우하면 친구가 되고, 친구의 프로필과 공개 작품을 볼 수 있습니다. 프로필 공개 범위는 전체·친구·비공개 중에 고릅니다.
* **토론 게시판:** 코딩 이야기를 나누는 게시판입니다. 글·댓글·신고를 지원하고, 서로 다른 3명이 신고하면 글이 자동으로 숨겨집니다.
* **전체 검색:** 내 작품, 친구 작품, 챕터를 한 번에 찾습니다.

### 8. 선생님 과제 (Assignments)

* 선생님이 반에 챕터를 과제로 내거나 직접 쓴 과제를 올릴 수 있고, 마감일과 보상 코인을 정합니다.
* 학생 대시보드에 과제가 뜨고 마감까지 남은 날짜를 보여줍니다. 챕터 과제는 통과하면 자동으로 완료되고, 직접 쓴 과제는 학생이 끝냈다고 표시합니다.
* 선생님은 과제별로 학생 한 명 한 명의 수행 현황(점수·제출 횟수·학생 메모)을 확인합니다.

## 블록 디자인 바꾸기 (Block Design)

블록의 색·글꼴·외형은 **`frontend/src/blockly/theme.js` 한 파일**에서 정합니다.

| 바꾸고 싶은 것 | 고칠 곳 (theme.js 안) |
| --- | --- |
| 카테고리별 블록 색 10가지 | `CATEGORY_COLOURS` |
| 🔍 찾기 칸 색 | `SEARCH_COLOUR` |
| 블록 전체 외형 (둥근 스크래치풍 ↔ 각진 기본) | `RENDERER` |
| 시작 블록 위 모자 | `START_HATS` |
| 블록 글꼴·굵기·크기 | `FONT` |
| 작업공간·팔레트 배경 (라이트/다크) | `CHROME` |
| 작업공간 점 격자 | `GRID` |

`CATEGORY_COLOURS`를 고치면 **블록 색 · 팔레트 카테고리 색 · 미션 패널의 블록 칩 색**이 함께 바뀝니다.

* 블록 정의 파일(`frontend/src/blockly/blocks.js`)에는 색상값이 없고 스타일 이름(`motion_style`)만 있습니다. 블록이 서로 끼워지는 구조는 블록의 동작이라 정의 파일에 남아 있습니다.
* 서버 재채점기(`backend/grader/grade.mjs`)는 `blocks.js`만 가져다 쓰므로, **디자인을 바꿔도 채점기를 다시 빌드할 필요가 없고 백엔드 파일도 바뀌지 않습니다.**
* 연산 칸의 비교·계산 블록과 변수 값 블록은 Blockly가 기본 제공하는 블록이라 Blockly 기본 색을 씁니다. 바꾸려면 `theme.js`의 `blockStyles`에 `logic_blocks` / `math_blocks` / `variable_blocks`를 추가하세요.

## 관리자 웹 (백엔드만 있음)

회원과 운영 기준값을 관리하는 화면입니다. **서버 쪽만 만들어져 있고 화면은 아직 없습니다.**

관리자는 `role`과 별개인 `users.is_admin` 플래그로 정합니다. 학생·선생님·보호자와 다른 축이라 역할을 늘리지 않았습니다.

**첫 운영자 지정** — 웹으로 자기를 운영자로 만드는 길은 일부러 두지 않았습니다. 서버에서 직접 지정합니다.

```
cd backend
php tools/make_admin.php 목록
php tools/make_admin.php 지정 admin@example.com
php tools/make_admin.php 해제 admin@example.com
```

배포본(`FTP업로드`)에는 `tools/` 폴더가 들어가지 않습니다. 관리용 스크립트가 웹에 올라가면 안 되기 때문입니다. 그래서 **실서버에서는 phpMyAdmin에서 SQL 한 줄로** 첫 운영자를 지정합니다.

```sql
UPDATE users SET is_admin = 1, token_version = token_version + 1
WHERE email = 'admin@example.com';
```

`token_version`을 올리는 건 그 계정이 들고 있던 토큰을 끊어서 다시 로그인하게 하려는 겁니다. 권한은 요청마다 DB에서 다시 읽으므로 안 올려도 동작하지만, 로그인 상태를 새로 맞추는 쪽이 깔끔합니다. 두 번째 운영자부터는 관리자 웹에서 지정할 수 있습니다.

| 주소 | 메서드 | 하는 일 |
| --- | --- | --- |
| `/api/admin/stats.php` | GET | 회원·학습·게시판·신고·코인 숫자, 최근 7일 가입자 |
| `/api/admin/users.php` | GET | 회원 목록 (`q`·`role`·`state`·`page`), `?id=N`으로 상세 + 활동 요약 |
| `/api/admin/users.php` | PATCH | 역할·운영자 권한·정지·정지 사유·보호자 동의·강제 로그아웃 |
| `/api/admin/users.php` | DELETE | 회원 탈퇴 처리 |
| `/api/admin/settings.php` | GET / PUT | 운영 기준값 읽기 / 저장·기본값 되돌리기 |
| `/api/admin/moderation.php` | GET / PATCH | 신고된 글·작품 목록과 신고 이유 / 숨기기·복구 |

**기준값**은 `settings` 표에 저장하고, 행이 없으면 `backend/config/Settings.php`의 `DEFAULTS`를 씁니다. 표가 비어 있어도 서비스는 그대로 돕니다. 지금 관리하는 항목은 코인 보상(출석·연속·챕터·자유창작·타자·퀴즈), 코코 하루 질문 수, 신고 자동 숨김 인원, 게시판 글쓰기 간격입니다.

항목마다 이름·설명·범위를 `GET`이 함께 돌려주므로, 화면에서 항목을 하드코딩하지 않고 입력칸을 그릴 수 있습니다. 기준값을 추가할 때 프론트를 같이 고치지 않아도 됩니다.

**잠김 방지** — 자기 운영자 권한을 뺄 수 없고, 자기 계정을 정지·탈퇴시킬 수 없고, 마지막 운영자의 권한도 뺄 수 없습니다.

**정지된 계정**은 로그인은 되지만 다른 API가 403으로 막히고, 사유가 응답에 들어갑니다. 401로 막으면 화면이 "로그인 풀림"으로 보고 조용히 로그아웃시켜서 학생이 이유를 알 수 없습니다.

관리자 웹을 다른 주소(포트)에 띄우면 `backend/.env`의 `ALLOWED_ORIGINS`에 그 주소를 추가해야 합니다.

## 내 컴퓨터에 DB 맞추기

처음 받았거나, 남이 올린 변경에 DB 칸이 추가됐을 때 쓴다. 둘 중 아무거나 하면 된다.

**1. 자동 (권장)** — `setup-db.bat`을 두 번 누른다. 접속 정보를 물어보고, DB가 없으면 만들고 있으면 새 기능에 맞게 고친 뒤 `backend/.env`에 저장한다.

**2. 손으로** — `DB.sql` 한 파일을 phpMyAdmin·HeidiSQL·MySQL Workbench 같은 곳에서 연다. 안이 두 구역으로 나뉘어 있으니 **내 상황에 맞는 구역 하나만** 실행한다. 둘 다 돌리면 `[A]`가 만든 테이블에 `[B]`가 또 컬럼을 넣으려 해서 오류가 난다.

| 내 상황 | 실행할 구역 |
| --- | --- |
| DB가 아예 없다 | `[A] 처음 설치용` |
| 쓰던 DB가 있는데 코드가 새 칸을 찾는다 | `[B] 기존 DB 업그레이드용` |

`DB.sql`은 `schema.sql`과 `migrations/upgrade.sql`을 이어붙인 것으로, `build-deploy.bat`을 돌릴 때마다 다시 만들어진다. 직접 고치지 말고 원본 두 파일을 고친다.

서버는 첫 요청에서 `backend/config/SchemaUpgrader.php`가 같은 내용을 자동으로 적용하므로, 보통은 둘 다 안 해도 화면을 켜는 것만으로 맞춰진다. DB 계정에 `ALTER` 권한이 없을 때만 위 방법이 필요하다.

## 배포하기 (FTP)

`build-deploy.bat`을 두 번 누르면 저장소 바깥의 `FTP업로드/public_html` 폴더가 최신 코드로 갱신됩니다. 그 안의 내용을 FTP로 서버 `public_html`에 덮어쓰면 됩니다.

| 갱신되는 것 | 내용 |
| --- | --- |
| `FTP업로드/public_html/` | 화면 + `backend/` (서버에 올릴 것) |
| `DB.sql` (저장소) | 위 "내 컴퓨터에 DB 맞추기"에서 쓰는 파일. 배포본의 `2-DB.sql`과 같은 내용 |
| `FTP업로드/2-DB.sql` | SQL 한 파일. 안에서 `[A]` 처음 설치용(`schema.sql`)과 `[B]` 기존 DB 업그레이드용(`migrations/upgrade.sql`)으로 나뉘며, 상황에 맞는 구역 하나만 실행 |

화면이 서버를 `/backend/api`로 부르도록 빌드됩니다. 이 주소는 `frontend/.env.production.local`에 있습니다.

서버 설정(`public_html/backend/.env`)과 웹 루트 설정(`public_html/.htaccess`)은 건드리지 않습니다. 지우고 다시 만든 뒤 원래 파일을 되돌려 놓습니다. 관리용 스크립트(`tools/`)와 로그는 빠집니다.

서버 재채점(`backend/grader/grade.mjs`)은 Node.js가 있어야 돕니다. 호스팅에 없거나 경로가 다르면 `.env`의 `NODE_BIN`에 적어주세요. Node가 없으면 채점만 멈추고 나머지 기능은 그대로 돕니다.

## Dream Builders

코코딩 플랫폼을 개발한 **Dream Builders**입니다. 아이들이 쉽고 즐겁게 코딩을 배울 수 있는 교육 환경을 만드는 것을 목표로 하고 있습니다.

* **김지원 (팀장)** | 프로젝트 매니저(PM) · UI/UX 디자이너 · 브랜딩

  * **프로젝트 총괄:** 프로젝트의 전체 기획과 일정 관리를 담당하며, 팀의 방향성과 서비스 완성도를 조율했습니다.
  * **UI/UX 디자인:** 초등학생 사용자의 눈높이에 맞춘 직관적이고 친근한 디자인 시스템을 구축하고, 블록 코딩 학습 공간 및 캐릭터 상점 등 주요 화면을 설계했습니다.

* **고청해** | QA 엔지니어 · 콘텐츠 기획자

  * **품질 보증 및 테스트:** 회원가입부터 블록 코딩 실행까지 서비스 전반의 기능 흐름을 검증하고, 사용자 관점에서 발생 가능한 오류를 사전에 점검했습니다.
  * **콘텐츠 기획:** 아이들의 학습 흥미를 높일 수 있도록 퀴즈와 미션의 구성 및 난이도를 기획·조율했습니다.

* **김해진** | 프론트엔드 엔지니어 · 기획 총괄

  * **프론트엔드 개발:** 디자인된 화면을 실제 웹 서비스로 구현하고, 사용자 인터랙션과 클라이언트 기능 동작을 개발했습니다.
  * **서비스 기획 총괄:** 팀의 아이디어를 구체적인 기능과 서비스 흐름으로 정리하며 개발과 기획을 연결하는 역할을 수행했습니다.

* **바허드르** | 서비스 기획자 · 화면 설계

  * **서비스 기획:** 아이들과 교육자(교사·학부모) 모두가 편리하게 사용할 수 있도록 서비스 시나리오와 핵심 기능을 기획했습니다.
  * **화면 구조 설계:** 사용자가 원하는 기능에 빠르게 접근할 수 있도록 직관적이고 체계적인 화면 구조를 설계했습니다.

* **박규성** | 백엔드 엔지니어 · 교육 콘텐츠 기획자 · 예산 운영 담당

  * **백엔드 및 데이터 설계:** 출석, 학습 진도, 보상 데이터 등이 안정적으로 저장·연동될 수 있도록 서버 및 데이터베이스 환경을 구축했습니다.
  * **교육 콘텐츠 기획:** 수준별 블록 코딩 미션과 퀴즈 콘텐츠를 설계하여 지속적인 학습 참여를 유도했습니다.
  * **예산 운영 관리:** 프로젝트 운영에 필요한 자원과 예산을 계획하고 효율적으로 관리했습니다.

* **이수진** | 프론트엔드 엔지니어 · 기능 설계 · 화면 설계

  * **프론트엔드 개발:** 디자인된 화면을 실제 웹 서비스로 구현하고, 사용자 인터랙션과 클라이언트 기능 동작을 개발했습니다.
  * **기능 정의:** 회원가입, AI 캐릭터 상호작용, 진단 설문 등 주요 기능의 세부 동작과 요구사항을 정의했습니다.
  * **화면 설계:** 기능 요소를 사용자 흐름에 맞춰 구조화하고, 일관성 있는 화면 설계 문서를 작성했습니다.
