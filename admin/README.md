# 코코딩 관리자 웹 (admin)

운영자가 회원과 신고된 글을 관리하는 별도 웹앱이에요. 학생 앱(`frontend/`)과 코드·토큰을 나눠 씁니다.

- 1차 범위: 로그인과 권한 확인, 대시보드, 회원 목록·상세·상태 변경, 신고 목록·상세·숨김·복구
- 2차 범위: 공지사항(목록·상세·작성·수정·삭제, 초안/게시, 고정, 받는 사람), 운영 기준값(서버 목록으로 화면 구성, 저장·기본값 복원)
- 범위가 아닌 것: 챕터, 아이템, 반, 운영 기록 화면, 학생 앱에 공지 보여 주기(학생 앱 쪽 별도 작업)
- API 기준: `docs/관리자웹-프론트-요청.md`와 현재 체크아웃의 `backend/api/admin/*.php` (main에 병합된 코드, 읽기만 함)

> **현재 상태**
> - **1차 화면(로그인·대시보드·회원·신고):** 백엔드 담당자가 PR #16의 관리자 앱을 실제 서버에 붙여 확인했어요(커밋 `b8664ee`). 화면 12장을 보고, 모의 응답과 실제 응답을 조회 8종·변경 18종 비교해 차이가 없었다고 적혀 있어요. 캡처는 `docs/pr16-check/`에 있어요(연습용 데이터만 보이는 화면). 프론트 담당이 직접 실제 서버로 다시 확인한 것은 아니에요.
> - **2차 화면(공지사항·운영 기준값):** 모의 응답으로만 확인했어요. 실제 서버에 읽기·쓰기 요청을 보낸 적이 없어요(공지 작성·삭제, 기준값 변경은 실제 서비스에 바로 반영되는 작업이라 실행하지 않았어요).

백엔드 담당자에게 전달할 확인 요청은 [BACKEND-HANDOFF.md](./BACKEND-HANDOFF.md)에 모았어요.

## 실행 (Windows PowerShell)

처음 한 번 패키지를 설치해요.

```powershell
cd admin
npm install
```

### 실제 API에 연결

백엔드 주소를 넣고 개발 서버를 켜요. 주소는 백엔드가 켜진 곳에 맞게 바꿔 주세요.

```powershell
$env:VITE_API_URL = 'http://localhost:8081/api'
npm run dev
```

- 개발 서버는 항상 **http://localhost:5175** 에서 켜져요(`strictPort`). 5175를 다른 프로그램이 쓰고 있으면 다른 포트로 바꾸지 않고 멈춰요.
- 백엔드 `.env`의 `ALLOWED_ORIGINS`에 `http://localhost:5175`가 있어야 해요. 백엔드 기본값과 `.env.example`에는 들어 있지만, 실제 서버 설정은 **확인하지 못했어요**.
- 서버에 연결하지 못하면 "연결 상태를 확인해 주세요", 서버 내부 오류(5xx)면 "서버에 문제가 생겼어요"가 떠요. 성공한 것처럼 꾸미지 않아요.

### 모의 데이터로 실행 (개발 전용)

백엔드 없이 화면을 확인할 때 써요. 모든 응답은 브라우저 메모리 안의 가짜 데이터이고, 실제 서버로는 아무것도 보내지 않아요.

```powershell
$env:VITE_ADMIN_MOCK = 'true'
npm run dev
```

- 화면 맨 위에 항상 **"모의 데이터"** 띠가 보여요.
- 모의 계정(비밀번호는 아무 글자나):
  - `admin@mock.test`: 운영자
  - `teacher@mock.test`: 운영자가 아님 → 권한 없음 화면
  - `suspended@mock.test`: 정지된 운영자 → 로그인은 되고, 관리자 화면에서 403과 정지 사유
- 탭을 새로 고치면 데이터가 처음으로 돌아가요.
- 개발자 도구 콘솔에서 쓰는 조작:
  - `__adminMock.fail('/admin/users.php', 500)`: 다음 한 번만 그 상태 코드로 실패 (JSON)
  - `__adminMock.fail('/admin/stats.php', 502, '', { html: true })`: 다음 한 번만 HTML 오류 페이지로 실패
  - `__adminMock.fail('/admin/stats.php', 401)`: 로그인이 끊긴 상황
  - `__adminMock.delay = 1500`: 응답 지연(ms)
  - `__adminMock.serverToday = '2026-11-18'`: `stats`의 `today`를 이 날짜로 바꿔 보냄 (기본은 이 PC의 오늘)
  - `__adminMock.legacyStats = true`: 옛 서버처럼 `today` 없이, 가입자가 있는 날만 보냄 (화면의 대체 기준 확인용)
  - `__adminMock.extraSignups = [{ day: '2030-01-01', count: 5 }]`: 가입자 그래프에 범위 밖 줄 추가
  - `__adminMock.nextDelays = [1500, 50]`: 다음 요청들의 지연을 차례로 지정 (늦게 온 응답이 새 화면을 덮지 않는지 확인)
  - `__adminMock.rejectSettings = ['coin.chapter']`: 기준값 저장 때 그 항목만 거절, `['*']`이면 전부 거절 (일부 성공·전체 실패 확인)
- 모의 공지는 23개(2쪽, 고정 2개, 초안 4개)이고, 모의 기준값은 `coin.chapter`만 기본값(50)에서 70으로 바뀐 상태로 시작해요.

모의 모드를 끄려면 환경 변수를 지우거나, PowerShell 창을 새로 열어요.

```powershell
Remove-Item Env:VITE_ADMIN_MOCK
```

### 모의 모드와 실제 서버의 차이

모의 응답은 현재 체크아웃의 백엔드 코드를 읽고 확인한 **검사 순서·문장·상태 코드를 흉내 낸 것**이에요. 서버 구현을 그대로 옮긴 것이 아니고, 실제 응답과 비교해 본 적도 없어요.

맞춘 것 (코드 기준):
- 정지된 계정도 로그인은 되고, 관리자 API에서 403과 정지 사유 문장을 받음
- 401 "로그인이 필요합니다.", 운영자가 아니면 403 "관리자만 쓸 수 있는 기능이에요."
- 회원 PATCH의 검사 순서와 400·404·409 문장, "바꿀 내용이 없어요", 코인·경험치 ±1,000,000 제한
- 로그아웃·권한 빼기·정지·역할·이메일 변경·임시 비밀번호 발급 때 그 회원의 모든 토큰을 끊음
- 신고 이유는 최신순, 받은 신고는 게시글 신고만 셈
- 가입자 그래프는 `today`와, 가입이 없던 날도 0으로 채운 7칸을 보냄 (모의 데이터는 2일 전·5일 전이 0)
- 마지막 운영자 보호는 **정지되지 않은 운영자 수**로 판단해 권한 빼기·정지를 막음 (`usableAdminCount`)
- 탈퇴하면 그 회원의 글·작품도 목록에서 사라짐
- 공지: 제목 1~80자·내용 1~2000자, `pinned`·`published`는 참/거짓, `audience`는 4가지 중 하나, 새 공지는 201, "바꿀 내용이 없어요", 404 "그런 공지가 없어요."
- 공지 목록은 고정 먼저·최신 번호 순, 한 쪽 20개, `hasMore`와 `audiences`를 함께 보냄 (`total`은 없음)
- 기준값: `settings` 항목 모양(`name·group·label·help·min·max·value·default·changed`), 범위 밖·정수가 아닌 값은 그 항목만 거절, 응답은 저장 결과와 상관없이 200, 거절이 없으면 `errors`가 `[]`(PHP 빈 배열)

모의 모드에만 있는 편의 동작 (실제와 다름):
- 비밀번호는 아무 글자나 맞음, 로그인 실패 횟수 제한(429)이 없음
- 토큰은 JWT가 아닌 임의 문자열이고, 메모리에만 있음
- '서버 시각'은 이 PC 시계를 씀 (실제 서버는 `APP_TIMEZONE`, 기본 Asia/Seoul)
- 대시보드의 학습·게시판·코인 숫자와 `activeWeek`는 고정값
- 회원 활동 요약 숫자는 계산식으로 만든 값
- 이메일 형식 검사는 PHP `FILTER_VALIDATE_EMAIL`보다 느슨함
- 무대 캡처는 없음(`thumbnail_url: null`)
- `__adminMock` 조작 (`legacyStats`로 옛 서버 응답 흉내 포함)
- 기준값 '모의 거절'(`rejectSettings`)은 실제 서버에 없는 실패예요. 실제 서버는 범위 밖 값·모르는 항목만 거절해요
- 기준값 목록은 `backend/config/Settings.php`의 항목을 모의 데이터로 옮겨 둔 것이에요. 화면은 응답으로 받은 목록만 그려요

## 검사와 빌드

### 추가 QA 보완

- 로그아웃 API가 401을 반환해도 처리 중 상태를 초기화해 재로그인 후 로그아웃 버튼을 다시 사용할 수 있게 했어요.
- 회원 변경이 시작되면 변경 전에 시작한 상세 조회를 무효화해, 오래된 GET 응답이 변경 결과를 덮지 않게 했어요.
- 처리 중 모든 버튼이 비활성화돼도 확인창 자체에 초점을 유지해요.
- 코인·경험치 증감량은 서버와 같은 ±1,000,000 범위의 정수만 허용해요.
- 정지는 로그인 자체의 차단이 아니라 서비스 이용 제한으로 안내해요.
- 회원 닉네임과 신고 제목은 실제 링크로 열고, 상세에서 돌아오면 목록의 원래 링크와 스크롤 위치를 복원해요.

위 예외 처리와 응답 순서는 실제 함수 코드를 이용한 메모리 내 모의 실행으로 확인했어요. 실제 API·DB와 브라우저의 키보드·화면 낭독기 재검증은 아직 하지 않았어요.

```powershell
npm run lint
```

```powershell
npm run build
```

```powershell
npm run preview
```

빌드 결과는 `admin/dist/`에 생겨요(git에 올리지 않음). 실제 서버 주소로 빌드할 때는 `npm run build` 앞에 `$env:VITE_API_URL`을 넣어요.

### 운영 빌드에 모의 코드가 없는지 확인

모의 코드는 `import.meta.env.DEV && …` 조건 안에서만 불러요(`client.js`, `LoginPage.jsx`, `Layout.jsx`의 `MockBanner`). 운영 빌드에서는 이 값이 `false`가 되어 코드가 빠지고, `mock.js`는 번들에 들어가지 않아요. 빌드 뒤 아래 명령의 결과가 비어 있으면 돼요.

```powershell
Select-String -Path dist\assets\*.js -Pattern 'mock.test','__adminMock','MOCK_LOGIN_HINT','mockFetch','모의'
```

## 화면과 주소

화면 주소는 해시 방식이라 서버 설정 없이 새로고침, 뒤로 가기, 주소 공유가 돼요.

| 주소 | 화면 |
| --- | --- |
| `#/dashboard` | 대시보드 |
| `#/users?q=&role=&state=&page=` | 회원 목록 (검색은 '찾기'를 눌러야 적용) |
| `#/users/52` | 회원 상세와 관리 |
| `#/moderation?target=post\|project&page=&id=` | 신고 목록과 상세 |
| `#/notices?page=` | 공지 목록 (초안 포함, 고정이 위) |
| `#/notices/new` | 새 공지 |
| `#/notices/12` | 공지 상세·고치기·지우기 |
| `#/settings` | 운영 기준값 |

## 공지사항

- 새 공지는 **올리기**(공개 상태로 저장)와 **초안으로 저장** 두 버튼으로 나눠요. 초안은 운영자만 볼 수 있어요.
- **학생·교사·보호자 앱에는 아직 공지를 보여 주는 화면이 없어요.** 그래서 확인 창은 "화면에 바로 보여요"가 아니라 "선택한 대상에게 공개하는 상태로 저장해요"라고 안내해요. 실제로 보이는지는 학생 앱 화면이 생긴 뒤에 확인해야 해요.
- 게시 상태가 바뀌는 저장(초안 → 게시, 게시 → 초안)은 확인 창을 한 번 더 띄워요. 확인 창에 받는 사람과 고정 여부를 보여 줘요.
- 고칠 때는 **바뀐 항목만** 보내요(`PATCH`). 바뀐 것이 없으면 요청을 보내지 않고 "바뀐 내용이 없어요"라고 알려 줘요.
- 지우기는 확인 창을 거치고 되돌릴 수 없다고 알려요. 잠시 내리기만 할 때는 초안으로 돌리라고 안내해요.
- 저장·삭제가 실패하면 입력과 선택을 그대로 두고 서버 문장(5xx는 일반 문구)을 보여 줘요. 처리 중에는 버튼을 막아 두 번 보내지 않아요.
- 작성·수정 중에 다른 화면으로 가거나 창을 닫으면 먼저 물어요.
- 상세에서 목록으로 돌아오면 보던 쪽과 누른 공지 링크로 초점·스크롤이 돌아가요.
- 받는 사람 값(`all·student·teacher·guardian`)은 서버 `notices.php`의 목록과 같아요. 화면 표시는 전체·학생·교사·보호자예요.

## 운영 기준값

- 항목 이름·묶음·설명·범위는 서버가 보내는 `settings` 배열로만 그려요. 화면에 항목 이름을 적어 두지 않아서, 서버에 기준값이 늘면 화면을 고치지 않아도 나타나요.
- 입력한 값은 바로 저장되지 않고 '바꿀 항목'으로 모였다가, **저장**을 누르면 확인 창에 항목마다 변경 전 → 후를 보여 줘요. 두 배 넘게 늘거나 최댓값이면 "크게 늘어요"로 표시해요.
- `changed`가 참인 항목에는 **기본값으로** 버튼이 있어요. 값 입력과 기본값 복원을 한 번에 보낼 수 있어요(`values`·`reset`).
- 저장은 '전부 아니면 전부'가 아니에요. 응답의 `saved`에 든 칸은 입력을 비우고 새 값으로 다시 그리고, `errors`에 든 칸은 **입력을 남긴 채 그 칸 아래에 이유**를 붙여요. 일부만 저장되면 노란 안내, 하나도 저장되지 않으면 빨간 안내예요.
- `errors`가 `[]`(빈 배열)로 와도, 객체로 와도 받아요. 응답에 `settings`·`saved` 배열이 없으면 성공으로 치지 않고, 저장됐는지 확인하라고 안내해요.
- 정수가 아니거나 범위 밖인 값은 보내기 전에 그 칸 아래에 알려 주고 저장 버튼을 막아요. 최종 판단은 서버예요.
- 기준값은 저장하는 순간 서비스에 반영돼요(서버에 캐시 없음).

## 로그인과 권한 규칙

- 토큰 저장 키는 `cocoding_admin_token`, 인증 이벤트는 `cocoding-admin:unauthorized`예요. 학생 앱과 섞이지 않아요.
- 운영자인지는 `role`로 판단하지 않고, `GET /admin/stats.php`가 200이면 운영자, 403이면 "권한 없음" 화면으로 판단해요. 권한 없음 화면에는 서버 문장을 그대로 보여 줘요.
- 각 작업에서 받은 403은 화면을 비우지 않고 그 자리에 서버 문장을 보여 줘요. 그와 함께 권한이 빠졌는지만 `stats`로 다시 확인해요.
- 401은 그 요청을 보낸 토큰이 지금 토큰과 같을 때만 로그아웃시켜요. 늦게 온 응답이 새 로그인을 끊지 않게 하려는 거예요.
- 4xx(400·404·409·429)는 서버가 사용자에게 보여 주려고 쓴 문장이라 그대로 보여 줘요.
- 5xx는 서버 문장을 보여 주지 않고 일반 문구와 상태 번호만 보여 줘요. 서버 문장에 내부 경로나 DB 설정 안내가 섞일 수 있어서예요. JSON이 아닌(HTML 등) 응답도 원문은 보여 주지 않아요.
- 비밀번호, 임시 비밀번호, 서버 응답 원문은 저장소(localStorage)나 콘솔에 남기지 않아요. 임시 비밀번호는 발급 직후 화면에만 보여요.
- **로그아웃:** 지금 서버는 로그아웃할 때 그 계정의 **모든 토큰을 끊어요**. 그래서 관리자 웹에서 로그아웃하면 같은 계정을 쓰는 다른 기기와 학생 앱에서도 다시 로그인해야 해요. 서버에 로그아웃을 알리지 못하면 "이 브라우저에서만 로그아웃했어요"라고 따로 안내해요.

## 대시보드 가입자 그래프의 날짜 기준

- 현재 백엔드 코드는 `stats`에 서버 기준 `today`와, 가입이 없던 날도 0으로 채운 최근 7일 `signups7d`를 보내요. 화면은 `today`를 기준일로 써요.
- `today`가 없거나 날짜 모양이 아니면(옛 서버) **Asia/Seoul 달력의 오늘**을 임시 기준으로 쓰고, 빈 날은 화면이 0으로 채워요. 관리자 PC의 시간대는 쓰지 않아요.
- 날짜 계산은 글자 날짜(UTC)로만 해서 PC 시간대·월말·연말·윤년에 영향을 받지 않아요.
- 7일 범위 밖(미래 포함)이거나 날짜 형식이 아닌 줄은 그리지 않고, 몇 줄을 뺐는지 그래프 아래에 적어요.
- 서버 시간대: 백엔드 코드는 `APP_TIMEZONE`(기본 Asia/Seoul)을 PHP와 DB 연결 모두에 적용해요. **실제 배포 서버의 `APP_TIMEZONE` 값은 확인하지 못했어요.**
