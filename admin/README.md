# 코코딩 관리자 웹 (admin)

운영자가 회원과 신고된 글을 관리하는 별도 웹앱이에요. 학생 앱(`frontend/`)과 코드·토큰을 나눠 씁니다.

- 1차 범위: 로그인과 권한 확인, 대시보드, 회원 목록·상세·상태 변경, 신고 목록·상세·숨김·복구
- 1차 범위가 아닌 것: 공지, 운영 기준값, 챕터, 아이템, 반, 운영 기록 화면
- API 기준: `관리자웹-프론트-요청.md`와 `backend/api/admin/*.php`(`origin/backend` 브랜치, 코드만 읽음)

> **현재 상태:** 모든 화면은 **모의 데이터로만** 확인했어요. 실제 관리자 API·DB와 연결해 확인한 것은 아직 없어요.
> 아래 '배포 전 확인'이 끝나야 실제 연동 검증을 할 수 있어요.

백엔드 담당자에게 전달할 확인 요청은 [BACKEND-HANDOFF.md](./BACKEND-HANDOFF.md)에 모았어요.

## 실행 (Windows PowerShell)

처음 한 번 패키지를 설치해요.

```powershell
cd admin
npm install
```

### 실제 API에 연결

백엔드 주소를 넣고 개발 서버를 켜요. 주소는 백엔드가 켜진 곳에 맞게 바꿔 주세요.

```powershell
$env:VITE_API_URL = 'http://localhost:8081/api'
npm run dev
```

- 개발 서버는 항상 **http://localhost:5175** 에서 켜져요(`strictPort`). 5175를 다른 프로그램이 쓰고 있으면 다른 포트로 바꾸지 않고 멈춰요.
- 백엔드 `.env`의 `ALLOWED_ORIGINS`에 `http://localhost:5175`가 있어야 해요. 백엔드 기본값과 `.env.example`에는 들어 있지만, 실제 서버 설정은 **확인하지 못했어요**.
- 서버에 연결하지 못하면 "연결 상태를 확인해 주세요", 서버 내부 오류(5xx)면 "서버에 문제가 생겼어요"가 떠요. 성공한 것처럼 꾸미지 않아요.

### 모의 데이터로 실행 (개발 전용)

백엔드 없이 화면을 확인할 때 써요. 모든 응답은 브라우저 메모리 안의 가짜 데이터이고, 실제 서버로는 아무것도 보내지 않아요.

```powershell
$env:VITE_ADMIN_MOCK = 'true'
npm run dev
```

- 화면 맨 위에 항상 **"모의 데이터"** 띠가 보여요.
- 모의 계정(비밀번호는 아무 글자나):
  - `admin@mock.test`: 운영자
  - `teacher@mock.test`: 운영자가 아님 → 권한 없음 화면
  - `suspended@mock.test`: 정지된 운영자 → 로그인은 되고, 관리자 화면에서 403과 정지 사유
- 탭을 새로 고치면 데이터가 처음으로 돌아가요.
- 개발자 도구 콘솔에서 쓰는 조작:
  - `__adminMock.fail('/admin/users.php', 500)`: 다음 한 번만 그 상태 코드로 실패 (JSON)
  - `__adminMock.fail('/admin/stats.php', 502, '', { html: true })`: 다음 한 번만 HTML 오류 페이지로 실패
  - `__adminMock.fail('/admin/stats.php', 401)`: 로그인이 끊긴 상황
  - `__adminMock.delay = 1500`: 응답 지연(ms)
  - `__adminMock.serverToday = '2026-11-18'`: 백엔드에 요청한 `today` 필드를 넣어 보냄
  - `__adminMock.extraSignups = [{ day: '2030-01-01', count: 5 }]`: 가입자 그래프에 범위 밖 줄 추가

모의 모드를 끄려면 환경 변수를 지우거나, PowerShell 창을 새로 열어요.

```powershell
Remove-Item Env:VITE_ADMIN_MOCK
```

### 모의 모드와 실제 서버의 차이

모의 응답은 `origin/backend`의 코드를 읽고 확인한 **검사 순서·문장·상태 코드를 흉내 낸 것**이에요. 서버 구현을 그대로 옮긴 것이 아니고, 실제 응답과 비교해 본 적도 없어요.

맞춘 것 (코드 기준):
- 정지된 계정도 로그인은 되고, 관리자 API에서 403과 정지 사유 문장을 받음
- 401 "로그인이 필요합니다.", 운영자가 아니면 403 "관리자만 쓸 수 있는 기능이에요."
- 회원 PATCH의 검사 순서와 400·404·409 문장, "바꿀 내용이 없어요", 코인·경험치 ±1,000,000 제한
- 로그아웃·권한 빼기·정지·역할·이메일 변경·임시 비밀번호 발급 때 그 회원의 모든 토큰을 끊음
- 신고 이유는 최신순, 받은 신고는 게시글 신고만 셈
- 가입자 그래프는 가입자가 있는 날만 보냄 (모의 데이터는 2일 전·5일 전이 비어 있음)
- 탈퇴하면 그 회원의 글·작품도 목록에서 사라짐

모의 모드에만 있는 편의 동작 (실제와 다름):
- 비밀번호는 아무 글자나 맞음, 로그인 실패 횟수 제한(429)이 없음
- 토큰은 JWT가 아닌 임의 문자열이고, 메모리에만 있음
- '서버 시각'은 이 PC 시계를 씀 (실제 서버 시간대는 미확인)
- 대시보드의 학습·게시판·코인 숫자와 `activeWeek`는 고정값
- 회원 활동 요약 숫자는 계산식으로 만든 값
- 이메일 형식 검사는 PHP `FILTER_VALIDATE_EMAIL`보다 느슨함
- 무대 캡처는 없음(`thumbnail_url: null`)
- `__adminMock` 조작, `today` 필드(아직 실제 서버에 없음)

## 검사와 빌드

### 추가 QA 보완

- 로그아웃 API가 401을 반환해도 처리 중 상태를 초기화해 재로그인 후 로그아웃 버튼을 다시 사용할 수 있게 했어요.
- 회원 변경이 시작되면 변경 전에 시작한 상세 조회를 무효화해, 오래된 GET 응답이 변경 결과를 덮지 않게 했어요.
- 처리 중 모든 버튼이 비활성화돼도 확인창 자체에 초점을 유지해요.
- 코인·경험치 증감량은 서버와 같은 ±1,000,000 범위의 정수만 허용해요.
- 정지는 로그인 자체의 차단이 아니라 서비스 이용 제한으로 안내해요.
- 회원 닉네임과 신고 제목은 실제 링크로 열고, 상세에서 돌아오면 목록의 원래 링크와 스크롤 위치를 복원해요.

위 예외 처리와 응답 순서는 실제 함수 코드를 이용한 메모리 내 모의 실행으로 확인했어요. 실제 API·DB와 브라우저의 키보드·화면 낭독기 재검증은 아직 하지 않았어요.

```powershell
npm run lint
```

```powershell
npm run build
```

```powershell
npm run preview
```

빌드 결과는 `admin/dist/`에 생겨요(git에 올리지 않음). 실제 서버 주소로 빌드할 때는 `npm run build` 앞에 `$env:VITE_API_URL`을 넣어요.

### 운영 빌드에 모의 코드가 없는지 확인

모의 코드는 `import.meta.env.DEV && …` 조건 안에서만 불러요(`client.js`, `LoginPage.jsx`, `Layout.jsx`의 `MockBanner`). 운영 빌드에서는 이 값이 `false`가 되어 코드가 빠지고, `mock.js`는 번들에 들어가지 않아요. 빌드 뒤 아래 명령의 결과가 비어 있으면 돼요.

```powershell
Select-String -Path dist\assets\*.js -Pattern 'mock.test','__adminMock','MOCK_LOGIN_HINT','mockFetch','모의'
```

## 화면과 주소

화면 주소는 해시 방식이라 서버 설정 없이 새로고침, 뒤로 가기, 주소 공유가 돼요.

| 주소 | 화면 |
| --- | --- |
| `#/dashboard` | 대시보드 |
| `#/users?q=&role=&state=&page=` | 회원 목록 (검색은 '찾기'를 눌러야 적용) |
| `#/users/52` | 회원 상세와 관리 |
| `#/moderation?target=post\|project&page=&id=` | 신고 목록과 상세 |

## 로그인과 권한 규칙

- 토큰 저장 키는 `cocoding_admin_token`, 인증 이벤트는 `cocoding-admin:unauthorized`예요. 학생 앱과 섞이지 않아요.
- 운영자인지는 `role`로 판단하지 않고, `GET /admin/stats.php`가 200이면 운영자, 403이면 "권한 없음" 화면으로 판단해요. 권한 없음 화면에는 서버 문장을 그대로 보여 줘요.
- 각 작업에서 받은 403은 화면을 비우지 않고 그 자리에 서버 문장을 보여 줘요. 그와 함께 권한이 빠졌는지만 `stats`로 다시 확인해요.
- 401은 그 요청을 보낸 토큰이 지금 토큰과 같을 때만 로그아웃시켜요. 늦게 온 응답이 새 로그인을 끊지 않게 하려는 거예요.
- 4xx(400·404·409·429)는 서버가 사용자에게 보여 주려고 쓴 문장이라 그대로 보여 줘요.
- 5xx는 서버 문장을 보여 주지 않고 일반 문구와 상태 번호만 보여 줘요. 서버 문장에 내부 경로나 DB 설정 안내가 섞일 수 있어서예요. JSON이 아닌(HTML 등) 응답도 원문은 보여 주지 않아요.
- 비밀번호, 임시 비밀번호, 서버 응답 원문은 저장소(localStorage)나 콘솔에 남기지 않아요. 임시 비밀번호는 발급 직후 화면에만 보여요.
- **로그아웃:** 지금 서버는 로그아웃할 때 그 계정의 **모든 토큰을 끊어요**. 그래서 관리자 웹에서 로그아웃하면 같은 계정을 쓰는 다른 기기와 학생 앱에서도 다시 로그인해야 해요. 서버에 로그아웃을 알리지 못하면 "이 브라우저에서만 로그아웃했어요"라고 따로 안내해요.

## 회원 탈퇴 안내의 근거

탈퇴 확인 창의 안내는 요청서와 저장소의 스키마 파일(`schema.sql`, `DB.sql`, `migrations/upgrade.sql`, `backend/config/SchemaUpgrader.php`)에 적힌 연쇄 삭제 범위를 기준으로 썼어요.

- 공통: 작품, 게시글, 댓글, 코인 기록, 출석, 학습 기록, 그리고 이 회원 게시글에 다른 사람이 단 댓글
- 선생님: 그 선생님이 만든 반과 과제 (반에 속한 학생 계정은 남음)
- 보호자: 자녀와의 연결 (자녀 계정은 남음)

실제 운영 DB가 이 스키마와 같은지는 아직 확인하지 못했어요(아래 '배포 전 확인').

## 대시보드 가입자 그래프의 날짜 기준

- 서버는 가입자가 있는 날만 `{ day: 'YYYY-MM-DD', count }`로 보내요. 화면이 빈 날을 0으로 채워 7칸을 만들어요.
- 기준이 되는 '오늘'은 서버가 `today` 필드를 주면 그 날짜, 없으면 **Asia/Seoul 달력의 오늘**을 임시로 써요. 관리자 PC의 시간대는 쓰지 않아요.
- 날짜 계산은 글자 날짜(UTC)로만 해서 PC 시간대·월말·연말·윤년에 영향을 받지 않아요.
- 7일 범위 밖(미래 포함)이거나 날짜 형식이 아닌 줄은 그리지 않고, 몇 줄을 뺐는지 그래프 아래에 적어요.
- **제한:** 서버(DB·PHP)의 시간대는 확인하지 못했어요. 서버가 서울 시간이 아니면 `today` 필드가 생기기 전까지 하루 어긋날 수 있어요.

## npm audit (점검일 2026-11-18)

`npm audit` 결과 high 5건이고, 모두 **picomatch의 ReDoS 한 가지**에서 나와요([GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf), 영향 버전 ≤4.0.7).

| 패키지 | 설치 버전 | 의존 | 이유 |
| --- | --- | --- | --- |
| picomatch | 4.0.7 | 간접 (vite, fdir, tinyglobby) | 취약점 본체 |
| fdir | 6.5.0 | 간접 | picomatch를 씀 |
| tinyglobby | 0.2.17 | 간접 | fdir, picomatch를 씀 |
| vite | 8.3.8 | 직접 (개발 도구) | 위 패키지를 씀 |
| @vitejs/plugin-react | 6.3.0 | 직접 (개발 도구) | vite를 씀 |

- **이전 작업 보고 기준 미해결:** 2026-11-18 점검 보고에서는 picomatch 최신 버전이 4.0.7이며 패치가 없다고 했어요. 버전·취약점 상태는 바뀔 수 있으므로 배포 전에 다시 확인해야 해요.
- **명령 실행 이력:** 이전 작업 보고에 `npm audit fix`(강제 아님)를 실행했고 바꿀 것이 없었다고 적혀 있어요. 이번 최종 점검에서는 설치·자동 수정을 실행하지 않았어요. `admin/` 전체가 아직 미추적 상태여서, 최초 설치 당시 사본이나 실행 로그 없이 과거 lock 파일 변경 여부를 Git으로 확정할 수는 없어요.
- `npm audit fix --force`는 vite를 6.2.7, plugin-react를 5.2.0으로 내리는 방법이에요. 메이저 버전을 내리는 일이라 하지 않았어요.
- **영향:**
  - 운영 빌드(`dist/`)에는 이 패키지들이 들어가지 않아요(빌드 결과에서 이름을 찾아 0건 확인).
  - 개발 서버와 빌드 과정에서는 쓰여요. 우리 코드와 설정의 파일 패턴만 처리한다고 보지만, 개발 서버가 받은 요청 경로가 어떤 식으로 처리되는지까지 확인하지는 않았어요. 그래서 **영향이 없다고 단정하지 않아요.**
  - 개발 서버는 기본으로 이 PC(localhost)에서만 열려요. 공용 네트워크에서는 `--host`로 열지 마세요.
- 할 일: picomatch 패치가 나오면 다시 `npm audit`으로 확인해요.
- 참고로 `frontend/`는 15건(high 10건)이 나오고, 그중 겹치는 것은 이 picomatch 계열뿐이에요.

## 배포 전 확인 (백엔드 담당)

연결 준비:
- [ ] `origin/backend`의 관리자 API(`backend/api/admin/`)를 띄운 서버
- [ ] DB 업그레이드(`users.is_admin`, `suspended`, `suspended_reason` 등)
- [ ] 운영자 시험 계정 1개(`tools/make_admin.php`, 백엔드 담당자가 지정)와 운영자가 아닌 시험 계정 1개
- [ ] 신고된 게시글·작품, 정지된 계정 같은 시험 데이터
- [ ] 실제 서버의 `ALLOWED_ORIGINS`에 `http://localhost:5175`가 들어 있는지

동작 확인:
- [ ] **연쇄 삭제:** 실제 운영 DB에도 스키마 파일과 같은 외래키·연쇄 삭제가 걸려 있는지, 표 엔진이 InnoDB인지
- [ ] 선생님을 탈퇴시키면 반과 과제가 모두 지워지는 것이 의도한 동작인지 (반을 넘기는 절차가 필요한지)
- [ ] 탈퇴로 코인 기록이 지워져 대시보드의 준 코인·쓴 코인 합계가 줄어드는 것이 괜찮은지
- [ ] **시간대:** DB(MySQL)와 PHP의 기준 시간대. `stats`의 `signups7d`와 `CURDATE()`는 DB 시간대, `consent_at`은 PHP 시간대를 따라요
- [ ] **가입자 그래프 응답:** 둘 중 하나를 요청해요. ① `signups7d`를 빈 날도 0으로 채워 항상 7개로 보내기 ② `stats`에 서버 기준 날짜 `today: 'YYYY-MM-DD'` 추가 (화면은 `today`를 이미 읽어요)
- [ ] **마지막 운영자 판정:** 서버의 운영자 수에 정지된 운영자도 들어가요. 정지되지 않은 운영자가 한 명뿐일 때 그 사람의 권한을 빼는 것을 막아야 하는지
- [ ] **로그아웃 범위:** 로그아웃이 그 계정의 모든 토큰을 끊는 것이 의도한 동작인지 (지금 화면은 이 동작을 기준으로 안내해요)
- [ ] **5xx 응답 문장:** DB 연결 실패(503) 응답에 `backend/.env`·`DB_HOST` 같은 내부 설정 안내가 들어 있어요. 화면에는 보여 주지 않지만, 응답 자체에서 빼 달라고 요청해요
- [ ] 위 항목이 끝나면 실제 API로 로그인·권한 없음·회원 변경·신고 숨김/복구를 다시 확인해요
