# 관리자 웹 1차 연동 확인 요청

로그인·권한 확인, 대시보드, 회원 관리, 신고 관리 화면을 `admin/`에 구현했습니다. 개발 전용 모의 응답으로 확인했으며 실제 관리자 API와 DB에는 연결하지 않았습니다.

실제 연동 전에 아래 사항을 확인 부탁드립니다. 프론트에서 DB 변경이나 관리자 권한 지정은 실행하지 않았습니다.

1. **운영 DB의 삭제 범위**: 실제 DB에도 저장소 스키마와 같은 외래키·연쇄 삭제가 적용돼 있는지, 관련 테이블이 InnoDB인지 확인 부탁드립니다. 화면에는 회원의 작품·글·댓글·코인·출석·학습 기록과 그 회원 글에 달린 타인의 댓글도 함께 삭제된다고 안내합니다.
2. **선생님 탈퇴**: 소유한 반·학생 참여 목록·과제가 함께 삭제되는 것이 의도한 동작인지, 탈퇴 전 반을 다른 선생님에게 넘겨야 하는지 확인 부탁드립니다. 학생 계정 자체는 유지되는 것으로 안내합니다.
3. **탈퇴 후 통계**: 코인 기록 삭제로 누적 지급·사용 합계가 줄어드는 현재 방식이 맞는지 확인 부탁드립니다.
4. **시간대**: DB와 PHP의 기준 시간대를 알려 주세요. 가입자 집계와 동의 시각 등이 같은 날짜 기준을 사용하는지 확인이 필요합니다.
5. **가입자 그래프**: `stats`에 서버 기준 `today: 'YYYY-MM-DD'`를 추가해 주실 수 있을까요? 또는 기준일을 포함한 최근 7일 배열을 0건인 날까지 반환해 주세요. 프론트는 `today`가 없으면 서울 날짜를 임시 기준으로 사용하므로 서버 날짜와 차이가 날 수 있습니다.
6. **마지막 운영자 보호**: 정지된 운영자도 관리자 수에 포함되는 것으로 확인했습니다. 이용 가능한 마지막 운영자의 권한 해제·정지를 막아야 하는지 확인 부탁드립니다. 프론트 비활성화와 별개로 서버 검증이 필요합니다.
7. **로그아웃 범위**: 로그아웃 시 같은 계정의 모든 토큰을 무효화하는 동작이 의도된 정책인지 확인 부탁드립니다. 현재 화면은 다른 기기와 학생 앱에서도 다시 로그인해야 한다고 안내합니다.
8. **5xx 응답**: DB 연결 실패 응답에 내부 파일 경로나 DB 설정명이 포함되지 않도록 일반 오류로 바꿔 주세요. 프론트는 5xx 원문을 숨기지만 응답 자체의 정리도 필요합니다.
9. **시험 환경**: 관리자 API가 실행되는 주소와 `http://localhost:5175` CORS 허용 여부를 확인해 주세요. 테스트 운영자·비운영자·정지 계정과 신고 게시글·작품을 준비 부탁드립니다. 비밀번호는 이 문서나 Git에 남기지 않고 별도 전달해 주세요.

조회부터 확인한 뒤, 회원 변경·삭제·숨김·복구는 합의된 시험 데이터에서만 검증하겠습니다. 운영자 지정·DB 업그레이드·배포 설정은 백엔드 담당자가 진행하는 범위입니다.
