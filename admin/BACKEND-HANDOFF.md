# 관리자 웹 연동 확인 요청 (2차: 공지사항·운영 기준값)

2차(공지사항, 운영 기준값) 화면을 `admin/`에 구현했습니다. 화면 동작은 개발 전용 모의 응답으로 확인했고, 백엔드는 현재 main에 병합된 코드와 PR #13~#17의 커밋 기록을 읽어서 대조했습니다. 2차 화면은 실제 서버 응답으로 확인한 것이 아직 없습니다.

## 1차 요청 9건 — 처리 완료 (커밋 `b8664ee`)

1차 요청은 모두 반영되거나 확인된 것을 커밋에서 확인했습니다. 다시 요청드리지 않습니다.

| 항목 | 처리 |
|---|---|
| 가입자 그래프 | `stats`가 `today`와 0을 채운 7일 배열을 반환 |
| 마지막 운영자 보호 | 정지되지 않은 운영자 수로 권한 해제·정지를 제한 |
| 서비스 시간대 | `APP_TIMEZONE`(기본 Asia/Seoul)을 PHP와 DB 연결에 적용 |
| DB 연결 오류(503) | 이 PC가 아닌 요청에는 일반 오류 문구를 반환 |
| 연습용 데이터 | `tools/practice_data.php` 추가 |
| 삭제 범위·선생님 탈퇴·코인 기록 삭제·로그아웃 범위·5175 CORS | 현재 동작 그대로 확인 (InnoDB, 외래키 34개) |

PR #16의 1차 화면을 실제 서버에 붙여 확인해 주신 결과(화면 12장, 조회 8종·변경 18종 비교, `docs/pr16-check/`)도 README에 반영했습니다.

남은 것은 **배포 서버**에서도 같은지입니다. 특히 배포 서버의 `APP_TIMEZONE` 값과 503 문구를 한 번 봐 주세요.

## 2차 검증에 그 서버를 써도 되는지 확인

새 시험 환경을 만들어 달라는 요청은 아닙니다. PR #16 확인에 쓰신 서버를 2차 검증에도 써도 되는지 확인 부탁드립니다.

1. **읽기 검증**: 공지 목록·상세, 기준값 목록 조회
2. **쓰기 검증**: 공지 작성·수정·삭제, 기준값 변경과 기본값 복원
   - 기준값은 저장 즉시 코인 지급 등에 반영됩니다. 그 서버를 다른 사람이 쓰고 있다면 알려 주세요.
3. **계정**: `practice_data.php`가 만드는 연습용 운영자 계정을 쓰면 되는지. 도구는 프론트에서 실행하지 않고, 비밀번호는 문서·Git에 남기지 않고 따로 받겠습니다.
4. **뒷정리**: 연습용 데이터 '지우기'로는 공지와 기준값 변경이 지워지지 않습니다(공지는 작성자만 비워지고 남음). 시험 공지는 제목에 `[시험]`을 붙여 검증 뒤 화면에서 지우고, 바꾼 기준값은 '기본값으로'로 되돌리겠습니다. 이 방식이면 괜찮은지 확인 부탁드립니다.

## 2차 관련 제안 — 급하지 않음

1. 공지 목록 응답에 전체 개수 `total`을 줄 수 있을까요? 지금은 `hasMore`만 있어 마지막 쪽 번호를 보여 줄 수 없습니다.
2. 기준값 저장 응답의 `errors`가 거절이 없을 때 `[]`로 나갑니다(PHP 빈 배열). `{}`로 맞출지 정해 주세요. 화면은 둘 다 받습니다.

- 학생·교사·보호자 앱에 공지를 보여 주는 화면이 아직 없습니다. 관리자 화면은 "선택한 대상에게 공개하는 상태로 저장"까지만 안내합니다. — 학생 앱 담당
- 게시판 작성 중·게임존 진행 중 브라우저 뒤로 가기에 이탈 확인이 없습니다. — 학생 앱 라우팅 담당
- 게임존의 코인 단가 안내는 로그인 세션마다 한 번만 불러와서, 기준값을 바꿔도 재로그인 전까지 옛 값이 보입니다(지급은 커밋 `e0f7696` 이후 새 값). — 게임존 담당
